## 二、客户端真实请求链（MITM 终结 TLS 实测）

```
1) POST https://fbaxapi.apiv2.a047.com/v2/auth/token
     UA: ua.net.fbclient.app.apex/v7.2.4
     body: {"email":"...","password":"..."}          -> 200 auth_data(JWT)

2) GET  https://fbaxapi.apiv2.a047.com/v2/account/profile
     Authorization: <JWT 原文>                        -> 200

3) GET  https://fbaxapi.apiv2.a047.com/v2/feed/access-token
     Authorization: <JWT 原文>                        -> 200 (含 access_key)

4) GET  https://fbaxsub.web.ak005.com/v2/feed/download?access_key=<key>
     UA: ua.net.fbclient.app.apex/v7.2.4
     X-Client-Platform: openwrt
     X-Client-Runtime-Abi: amd64
     X-Client-Environment: unknown
     (mTLS 客户端证书由二进制内置/协商)                -> 200 APXS 26858 B
```

要点：
- `Authorization` 是**裸 JWT**，不是 `Bearer <jwt>`；
- 订阅域名走 `fbaxsub.web.ak005.com`（解析到 `axapi-overseas.*` = <overseas-edge-ip>），
  与 `fbaxsub.apiv2.a047.com` 等价；缺 UA 或缺证书都会返回 404 伪装页；
- 客户端在本机**没有**请求 `tcdn-ax.getxlx.com/apos/fb_apexv2.json`（该端点当前 500），
  直接用二进制内置密钥完成解密 → **APXS 解密不依赖下发配置**。

## 三、为什么 `/start` 仍报“加载失败”

解密成功、明文已生成，失败发生在**后续把配置应用给内核**的阶段（`running:false`、
7890 未监听、无 `/dev/net/tun` 打开、无 nft 建表）。
对本任务无影响：**明文在失败前已经生成并驻留内存**，可直接抓取。

## 四、YAML 提取方法（核心）

1. 客户端解密后的订阅明文是 Go 堆里的一串 YAML；节点块各自独立分配；
2. 扫描 `/proc/<pid>/mem` 的所有匿名可读区段，定位 `xtls-rprx-vision` 标记；
3. 向后取 400 B，用字段级正则逐个还原
   `flow / name / network / port / server / servername / skip-cert-verify / tls / type / udp / uuid`；
4. 按 `name` 去重合并，全部 74 个节点即可在 1–2 秒内收齐；
5. 生成标准 mihomo 配置（含 `proxy-groups` 与 `rules`），`mihomo -t` 校验通过。

工具：`poc/linux/extract_nodes.py`（服务器端运行）。

```bash
# 触发一次拉取，同时抓取
python3 extract_nodes.py --pid $(pgrep -f apex-openwrt) --seconds 22 --out /tmp/sub_final.yaml &
curl -s --unix-socket /tmp/apex-mihomo/control.sock -X POST http://localhost/start -d '{}'
```

## 五、运行前提（硬性）

1. **必须关闭磁盘 swap**：客户端启动时校验，检测到 swap 直接拒绝
   （`secure memory policy unavailable`）；测完立刻 `swapon /swapfile`；
2. 运行目录必须是 **tmpfs**（`router runtime requires tmpfs`）；
3. geodata 必须在 `/usr/share/apex-mihomo/geodata/`
   （`ASN.mmdb`、`geoip.metadb`、`GeoSite.dat`）；
4. **必须在独立 netns 内运行**：它会建 `inet apex_mihomo` 表并加 `ip rule pref 10999`，
   在非 OpenWrt 宿主上会劫持宿主机出站流量（本轮已踩过一次，导致 SSH 失联）；
5. netns 内若要走外网，需为测试网段放行转发：
   `iptables -I FORWARD -s <ip>/24 -j ACCEPT`（对称一条）+ `MASQUERADE`。

## 七、结论与后续

- **目标达成**：不依赖 Windows、不依赖 APXS 密钥，靠官方 Linux 客户端即可拿到完整订阅 YAML；
- `servername` 每次拉取都会变，因此每次刷新后都需要重新提取（一条命令，约 25 s）；
- 若要长期稳定，建议把「netns 启动 → login → start → 抓取 → 校验 → 原子发布」串成脚本，
  并在每步前后做 swap / hosts / nft 对照；
- 生成的 `http/server_74_nodes.yaml` 可直接用于 mihomo/clash 客户端分发。
