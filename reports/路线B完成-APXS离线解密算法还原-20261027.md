# 路线 B 完成：APXS v2 离线解密算法还原（gdb 实证）

- 日期：2026-10-27
- 方法：pclntab 解析定位 Go 函数 → gdb 下断点 → 抓 `key32` / `OpenAPXS` 真实入参 → 已知明文反推
- 结论：**APXS 不需要官方客户端即可解密**，算法为 **AES-256-CTR**（GCM 计数器派生），密钥为内置常量 k1
- 验证：3 份独立样本全部解开，各含 74 节点 / 3 分组 / 14 规则

---

## 一、地址定位（无需符号表）

二进制 `-s -w` 剥离，但 Go 的 **pclntab** 保留。自写解析器（`poc/pclntab2.py`）按
`magic 0xF1FFFFFF + pad + minLC + ptrSize` 校验后解出 51,917 个函数名→地址：

| 函数 | 地址（x86_64，ET_EXEC，非 PIE） |
|---|---|
| `apexopenwrt.key32` | `0x77e8a0` |
| `apexopenwrt.OpenAPXS` | `0x77e980` |
| `apexopenwrt.OpenOSS` | `0x77efa0` |
| `apexopenwrt.RouterConfig` | `0x779240` |
| `apexopenwrt.Wipe` | `0x776ae0` |

> arm64 构建对应地址为 `0x329440 / 0x329530 / 0x3299e0 / 0x324f10`，同一套方法。

## 二、gdb 抓到的真实入参

```
### key32 entry  len=44   xZ//fP0AfP+8yW4OAZOrcKHe7dO78+Gpwu1ewno/fd8=   (调用 2 次)
### key32 entry  len=44   fCA3jkvhXpLEpDVuqPstNUS/kXewk7yGL5o8Fbh3uSc=
### key32 entry  len=44   lmzs43izW9GHIOOq+avbwhWh0TG/ldT3kipGkrQ4RiE=

### OpenAPXS entry
body = 0xc0008e1000  len = 26780
aes  = 0xc0007a2b70  len = 32      ← 解码后正是 k1
sign = 0xc0007a2ba0  len = 32      ← 解码后正是 k2
ids  = 0x0000000100000001          ← aesID=1, signID=1

### OpenAPXS return
rax = 0xc0008bca80  rbx = 26806    ← 明文长度
```

→ **内置常量就是真密钥**，之前"密钥由服务端下发"的判断作废。

## 三、格式与解密算法

```
偏移        内容
[0:4]       "APXS"
[4]         0x02（版本）
[5:9]       BE u32 aesID      (=1)
[9:13]      BE u32 signID     (=1)
[13:25]     nonce (12 字节)
[25:...]    密文
尾部 80B    16B 校验 + 64B（Ed25519 签名 / 或其他 MAC）
```

**解密**：AES-256-CTR，密钥 `k1`，计数器 = `nonce || 0x00000002`（即 GCM 的 J0+1）。

验证方式（已知明密文对，逐块比对）：

```python
ctr = Counter.new(32, prefix=nonce, initial_value=2, little_endian=False)
plain = AES.new(k1, AES.MODE_CTR, counter=ctr).decrypt(ct)
# plain == gdb dump 出的明文，完全一致
```

**关键发现**：尾部 16 字节**不是**标准 GCM tag —— 用 `AESGCM(k1).decrypt()` 配任何 AAD
（空 / 头 13B / nonce / 签名 / 各种拼接，共 2,500+ 组合）全部验签失败，
而纯 CTR 解密与官方输出**逐字节一致**。说明该实现只用 GCM 的计数器流做加密，
完整性由尾部 64 字节签名单独承担（这也是为什么我们不需要 tag 就能还原明文）。

## 七、完整的"无客户端"链路

```
1) POST https://fbaxapi.<domain>/v2/auth/token        {"email","password"}       → JWT
2) GET  /v2/feed/access-token   Authorization: <JWT 原文>                        → access_key
3) GET  https://fbaxsub.<domain>/v2/feed/download?access_key=...
        headers: UA "ua.net.fbclient.app.apex/v7.2.4" + mTLS 客户端证书           → APXS
4) python3 apxs_decrypt.py apxs.bin sub.yaml                                    → 明文 YAML
```

不再需要 40MB 的 Go 二进制，也不再需要提取内存。

## 八、注意事项

1. `sign_id` / `aes_id` 目前恒为 1；若服务端换 key id，需要重新抓一次内置常量；
2. 订阅域名会解析到 `axapi-overseas.*`（<overseas-edge-ip>），UA 与客户端证书缺一即 404；
3. `servername` 每次拉取轮换，务必每次重新下载 + 解密，不能复用旧 YAML；
4. 内置常量属于厂商私有实现，仅可在授权沙箱内用于互通性研究。
