## 三、登录态能否维持：能，三条路

### 3.1 JWT 有效期 72 小时

```
iat=1792991103  exp=1793250303  ttl=259200s = 72.0h
payload: {"uid":711447,"sub":"711447","exp":...,"iat":...}
```
续期方式：**重新登录**（`auth_data` 每次都换新，`token` 不变）。

### 3.2 落盘位置（DPAPI 加密）

`%APPDATA%\com.fbapp.clients.apex\飞鸟-极速版\flutter_secure_storage.dat`（550 B）

解开后（`poc/unseal_secure_storage.py`）：

```json
{"apex_profile_file_key_v3":"<16B b64>",
 "xboard_token":"<JWT>",
 "xboard_saved_password_v2":"<明文密码>"}   ← 安全性问题：密码可逆存储
```

`xboard_token` 与运行内存里的 JWT 完全一致；**该 JWT 在 fbesa 上可直接用**（`/user/info` 200）。

### 3.3 三条维持路径

| 路径 | 做法 | 适用 |
|---|---|---|
| A. 直接复用 JWT | 从 DPAPI 解出 `xboard_token`，直接 `Authorization: Bearer` | 72h 内，零网络依赖 |
| B. 重新登录（v1） | `POST https://fbesa.apiv2.a047.com/api/v1/passport/auth/login` | 长期，需要账号密码 |
| C. 客户端在线时导出 | 运行中进程内存 / DPAPI 文件 | 只在客户端能登录时 |

**建议**：以 B 为主（每 48h 一次），A 作为即时兜底；`token`（订阅 token）全局稳定，可长期缓存。

## 四、客户端缓存解封（新证据）

`shared_preferences.json` 里三个 `apex-url-v2:` 密文，用 `apex_profile_file_key_v3` 做 AES-128-GCM 可解：

信封结构：`"APEX" + 0x02 + nonce(12) + ct + tag(16)`（AAD 为空）

| 字段 | 明文 |
|---|---|
| `xboard_domain_subscription.subscribeUrl` | `https://api.example.com/api/v1/client/subscribe?token=<SUB_TOKEN>` |
| `flutter.config.profiles[0].url` | 同上（订阅配置的 URL） |
| `xboard_domain_subscription.token` | `<SUB_TOKEN>`（同值） |

**关键推论**：客户端把订阅 URL 里的 `token` 直接当作 `access_key` 用（配置映射 `/api/v1/client/subscribe?token=` → `/v2/feed/download?access_key=`）。所以 v2 恢复后，请求一定是：

```
GET https://fbaxsub.<域>/v2/feed/download?access_key=<SUB_TOKEN>
```
