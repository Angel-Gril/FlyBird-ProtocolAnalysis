# 证书用途分层与配置文件来源（2026-10-27 突破记录）

## 一、最重要的发现：mTLS 证书按用途分 vhost

用三套客户端证书（api / subscription / oss）× 三个 vhost 交叉测试：

| 证书 | vhost | 路径 | 结果 |
|---|---|---|---|
| **api** | `fbaxapi.apiv2.a047.com` | `/v2/feed/download?access_key=` | ✅ 200，26.8 KB **APXS** |
| **api** | `fbaxapi.web.ak005.com` | 同上 | ✅ 200，26.8 KB APXS |
| api | `fbaxsub.apiv2.a047.com` | 同上 | ❌ 404（153B nginx） |
| **subscription** | `fbaxsub.apiv2.a047.com` | `/v2/feed/download?access_key=` | ✅ **200，26.8 KB APXS** |
| subscription | `fbaxapi.*` | 同上 | ❌ 404 |
| oss | 所有 vhost | 同上 | ❌ 404 |

结论：**证书用途与 vhost 严格绑定**。这也解释了之前 `fbaxsub` 一直 404 —— 我们拿 api 证书去打它。

`fbaxsub` 上除 `/v2/feed/download` 外，其余路径（`/v2/feed/config`、`/apos/fb_apexv2.json`、
`/api/v1/client/subscribe` 等 18 条）全部 404。

## 二、客户端刷新时真正连的主机（pktmon SNI）

```
fbaxapi.apiv2.a047.com      -> <edge-ip>:443   (4x)
fbaxapi.web.ak005.com       -> <edge-ip>:443   (4x)
fbaxsub.apiv2.a047.com      -> <edge-ip>:443   (2x)   ← 订阅专用
<ip>                -> <ip>:443      (2x)   ← 配置镜像
apisa-ax.cnossfile.com      -> <cdn-ip>:443     (2x)   ← 配置镜像
ipinfo.io / ipapi.co / ipwho.is / api.ip.sb          (geo)
```

客户端**确实访问 `fbaxsub`**（订阅专用 vhost），而该 vhost 只提供 `/v2/feed/download` 的 APXS。
→ **客户端必然执行 APXS 解密**，"不走解密"的推断被推翻。

## 三、密钥只能来自配置

- 内置常量 k1/k2 对真实 APXS 的 GCM 认证全部失败（3 万+ 组合）
- 客户端每次刷新都拿到新配置（servername 每次不同）
- 因此解密用的密钥来自**远程配置**（`fb_apexv2.json`），不是内置常量

客户端同时访问 `<ip>` 与 `apisa-ax.cnossfile.com`，这两个正是 `fb_apexv2.json` 的镜像。
我们直接 GET 得 404，客户端却能成功 —— 说明请求带了**额外参数/签名/头**。

## 四、下一步：读配置文件的 URL 构造代码

需要 Blutter 输出里这几个文件的 asm（当前包里没有）：

```
apex_client/account/config/fetchers/remote_config_manager.dart
apex_client/account/config/board_config.dart
apex_client/account/config/utils/config_file_loader.dart
apex_client/account/config/core/module_initializer.dart
apex_client/account/config/core/service_locator.dart
```

从里面能直接读出：

- `fb_apexv2.json` 的完整 URL（是否带 `?t=&s=` 之类签名参数）
- 请求头（`x-apex-helper` / `_apex_nonce` / `apex-file-content` 的实际取值规则）
- 响应体解密方式（配置层是否也是 APXS）

拿到配置 JSON 后，里面的 `keys[{id, aes, sign}]` 就是 APXS 的密钥。
