# 纯协议抓取服务上线（替代 OpenWrt 客户端方案）

- 日期：2026-10-27
- 目标机：<server-ip>（Ubuntu 24.04 x86_64）
- 变更：`apex-fetch.service` 内部实现由「官方 OpenWrt 客户端 + netns + 内存提取」
  换成「纯 HTTPS 协议 + 本地 AES-256-CTR 解密」
- 结果：单次抓取 **≈8 秒**，74 节点 / 3 分组 / 14 规则，产物与 Private Subscription 缓存均正常

---

## 一、新旧方案对比

| 维度 | 旧（客户端 + 内存） | 新（纯协议） |
|---|---|---|
| 依赖 | 48 MB Go 二进制 + geodata | 无（仅 python3 + openssl） |
| 运行环境 | 独立 netns + veth + NAT | 普通进程，无网络改动 |
| swap | 必须临时关闭 | 不需要 |
| 单次耗时 | 25–45 s（等解密+扫描） | **≈8 s** |
| 失败恢复 | 需要清理 nft/ip rule | 无副作用 |
| 密钥 | 需要运行时从内存提取 | 内置常量 k1 |
| 产物 | 内存重建（可能缺 DNS 段） | **原始 YAML（含 dns/规则）** |

## 三、登录也需要客户端证书（本轮新发现）

之前以为只有下载要 mTLS，实测：

| 请求 | 无证书 | 带 api 证书 |
|---|---|---|
| `POST /v2/auth/token` | 404（nginx 伪装页） | **200** |
| `GET /v2/feed/access-token` | 404 | 200 |
| `GET /v2/feed/download` | 404 | 200（需 **subscription** 证书，混用也 404） |

→ 证书按 purpose 绑定 vhost，两张证书缺一不可。

## 七、后续维护

1. 客户端升级会更换证书 → 重新从客户端目录导出 4 个文件覆盖 `/etc/apex-fetch/certs/`；
2. 若服务端更换 AES key id，需要重新抓一次内置常量（pclntab + gdb 流程已记录在
   `reports/路线B完成-APXS离线解密算法还原-20261027.md`）；
3. `servername` 每次下发轮换，必须每次抓取，不能缓存复用。
